# 🖼️ Vectorizer — เอกสารประกอบโครงงาน (Project Documentation)

> **ชื่อโครงงาน**: Vectorizer  
> **แพลตฟอร์ม**: แอปพลิเคชันเดสก์ท็อปด้วย JavaFX  
> **หน้าที่หลัก**: แปลงรูปภาพบิตแมป (JPG / PNG) หรือไฟล์บีบอัด (ZIP) เป็นภาพเวกเตอร์แบบแบ่งเลเยอร์ (SVG) แบบกลุ่ม (Batch)  
> **สถาปัตยกรรมและเทคโนโลยี**: Java 24 (เข้ากันได้กับ LTS) · JavaFX · Potrace CLI · Log4j2 · Maven

---

## 1. สถาปัตยกรรมโดยรวมของระบบและรูปแบบการออกแบบ (Architecture & Design Pattern)

โครงงานนี้ได้รับการออกแบบตามรูปแบบสถาปัตยกรรม **MVC (Model-View-Controller)** อย่างเคร่งครัด พร้อมทั้งแยกส่วนเครื่องมือช่วยเหลือ (Util) เพื่อให้โค้ดมีความเป็นอิสระต่อกัน (Low Coupling) และจัดการได้ง่าย (High Cohesion):

```
se233.vectorizer
├── model          // แบบจำลองข้อมูลและเซอร์วิสการประมวลผลเวกเตอร์ (Business Logic)
├── view           // ส่วนติดต่อผู้ใช้และเลย์เอาต์ JavaFX (Presentation Layer)
├── controller     // ตัวควบคุมการทำงานและจัดการเหตุการณ์ (Controller Layer)
├── util           // คลาสช่วยเหลือ (ตรวจสอบไฟล์, แตกไฟล์ ZIP, วิเคราะห์สี)
└── exception      // คลาสข้อผิดพลาดที่กำหนดขึ้นเอง (Custom Exceptions)
```

* **Model (โมเดล)**:
  * `VectorizationService`: รับผิดชอบการสุ่มตัวอย่างพิกเซล, การจัดกลุ่มสีด้วยอัลกอริทึม K-Means (Color Quantization), การสร้างหน้ากากสีในรูปแบบ PPM, การเรียกใช้ Potrace CLI ภายนอก และการรวมเลเยอร์ SVG เข้าด้วยกัน
  * `ImageItem`: อ็อบเจกต์ตัวแทนของรูปภาพแต่ละรูป จัดเก็บไฟล์ต้นฉบับ อ็อบเจกต์รูปภาพ ที่อยู่ของไฟล์ SVG และการตั้งค่าเฉพาะของรูปภาพนั้น
  * `ConversionSettings`: จัดเก็บการตั้งค่าการแปลงภาพ (ระดับความละเอียด, โหมดสี, กฎการตั้งชื่อไฟล์ส่งออก)
* **View (มุมมอง)**:
  * `MainView`: เลย์เอาต์หลักของหน้าจอ ประกอบด้วยพื้นที่แสดงตัวอย่าง, แผงควบคุมการตั้งค่า, แถบเครื่องมือย่อ-ขยาย (Zoom) และแถบสถานะด้านล่าง
  * `DropZonePane`: พื้นที่รองรับการลากและวางไฟล์ (Drag and Drop) รับไฟล์รูปภาพหรือไฟล์ ZIP
  * `PreviewPane`: หน้าจอเปรียบเทียบรูปภาพต้นฉบับและภาพเวกเตอร์แบบแบ่งฝั่งซ้าย-ขวา โดยใช้ `ImageView` แสดงภาพต้นฉบับ และใช้ `WebView` (WebKit) แสดงผลภาพ SVG แบบเวกเตอร์ได้อย่างคมชัด
  * `ConfigPane`: แผงควบคุมด้านข้าง สำหรับปรับแต่งพารามิเตอร์การแปลงภาพ
* **Controller (ตัวควบคุม)**:
  * `MainViewController`: ตัวควบคุมหลัก จัดการลำดับคิวของรูปภาพ, การควบคุมเธรด (Thread Scheduling), การทำ Debounce สำหรับการพรีวิว และการเชื่อมต่อผลลัพธ์แบบ Asynchronous
  * `BatchProcessor`: ตัวประมวลผลแบบกลุ่ม ทำงานคู่ขนานเพื่อเตรียมพรีวิวรูปภาพล่วงหน้า (Preprocessing) และส่งออกไฟล์ SVG แบบกลุ่ม (Export)
  * `AllEventHandlers`: ตัวเชื่อมต่อเหตุการณ์ (Event Wiring) นำการกระทำจาก View ไปเรียกใช้ฟังก์ชันใน Controller เพื่อให้ View และ Controller แยกออกจากกันอย่างชัดเจน

## 2. ฟังก์ชันการทำงานหลักและหลักการทำงานของโค้ด (Features & Principles)

### ฟังก์ชันที่ 1: การนำเข้าไฟล์และไฟล์บีบอัด (Drag & Drop & ZIP Extraction)
* **คลาสที่เกี่ยวข้อง**: 
  * `DropZonePane.java` (การตรวจจับการลากและวาง)
  * `FileValidator.java` (การตรวจสอบนามสกุลไฟล์)
  * `ZipHandler.java` (การแตกไฟล์ ZIP และความปลอดภัย)
  * `MainViewController.java#loadFiles()` (การโหลดและป้องกันไฟล์ซ้ำ)
* **หลักการและความรู้ที่ใช้**:
  * **JavaFX Drag-and-Drop**: ดักฟังเหตุการณ์ `DRAG_OVER` เพื่อกำหนด `TransferMode.COPY` และเหตุการณ์ `DRAG_DROPPED` เพื่อดึงรายชื่อไฟล์จาก `Dragboard`
  * **การแตกไฟล์ด้วยสตรีม**: ใช้ `java.util.zip.ZipInputStream` อ่านไฟล์ภายใน ZIP และบันทึกลงในโฟลเดอร์ชั่วคราว (Temp Directory) ของระบบ
  * **การป้องกันช่องโหว่ ZIP Slip**: มีการตรวจสอบความปลอดภัยของไฟล์ที่แตกออกมาด้วยคำสั่ง `output.startsWith(extractionRoot)` เพื่อป้องกันการโจมตีประเภท Path Traversal ที่อาจเขียนทับไฟล์ระบบผ่านชื่อไฟล์อันตรายเช่น `../../`
  * **โค้ดที่เข้าใจง่าย**: ใช้ลูป `for` แบบพื้นฐานในการตรวจสอบชนิดและนามสกุลไฟล์ ช่วยให้เข้าใจง่ายและสามารถวาง Breakpoint ดีบักทีละบรรทัดได้อย่างชัดเจน

---

### ฟังก์ชันที่ 2: การวิเคราะห์และนับจำนวนสีอย่างรวดเร็ว (Color Analyzer)
* **คลาสที่เกี่ยวข้อง**: `ColorAnalyzer.java`
* **หลักการและความรู้ที่ใช้**:
  * **การสุ่มตัวอย่างพิกเซล (Sampling)**: สำหรับรูปภาพขนาดใหญ่ที่มีหลายล้านพิกเซล ระบบจะคำนวณระยะก้าว (Step) ในการสุ่มเพื่อไม่ให้การวนลูปทุกพิกเซลทำให้โปรแกรมค้าง
  * **การจัดการบิตของสี (Bitwise Operation)**: ใช้คำสั่ง `image.getRGB(x, y) & 0x00FFFFFF` เพื่อตัดช่องสัญญาณความโปร่งใส (Alpha Channel 8 บิตบน) ออก และเก็บเฉพาะค่าสี RGB แท้จริง
  * **การตัดการทำงานล่วงหน้า (Early Exit)**: ใช้ `HashSet` เก็บค่าสีเพื่อตัดค่าที่ซ้ำซ้อน หากพบสีที่แตกต่างกันเกินกว่าจำนวนที่ระบบรองรับสูงสุด (5 สี) ระบบจะหยุดสแกนทันทีเพื่อประสิทธิภาพสูงสุด

---

### ฟังก์ชันที่ 3: กระบวนการแปลงเป็นเวกเตอร์ (Vectorization Core)
* **คลาสที่เกี่ยวข้อง**: `VectorizationService.java`
* **ขั้นตอนการทำงานหลัก**:
  1. **การลดทอนและจัดกลุ่มสีด้วย K-Means (Color Quantization)**:
     * รูปภาพบิตแมปทั่วไปมีสีไล่ระดับจำนวนมาก ไม่สามารถนำไปตัดเส้นเป็นเวกเตอร์ได้โดยตรง ระบบจึงใช้อัลกอริทึม **K-Means Clustering** (วนซ้ำ 8 รอบ) เพื่อจัดกลุ่มพิกเซลทั้งหมดให้เหลือเฉพาะกลุ่มสีหลัก $K$ สี (1 ถึง 5 สี) ตามที่ผู้ใช้กำหนด
     * **สูตรระยะห่างของสี (Euclidean Distance)**: ใช้ผลรวมกำลังสองของผลต่างค่าสี $(R_1-R_2)^2 + (G_1-G_2)^2 + (B_1-B_2)^2$ โดยไม่ถอดสแควร์รูท เพื่อความรวดเร็วในการคำนวณ
  2. **การสร้างหน้ากากโมโนโครม (PPM Mask File)**:
     * สำหรับแต่ละเลเยอร์สีที่ได้จากการจัดกลุ่ม ระบบจะสร้างไฟล์ภาพขาว-ดำแบบ PPM (P6 Binary) โดยให้พิกเซลของสีนั้นเป็นสีดำ และสีอื่นเป็นสีขาว เพื่อเตรียมส่งให้ Potrace
  3. **การทำงานร่วมกับกระบวนการภายนอก (ProcessBuilder & Potrace CLI)**:
     * รันคำสั่งภายนอกผ่าน `ProcessBuilder`:
       ```text
       potrace -s -o <output.svg> -t <turdsize> -C <hexColor> <input.ppm>
       ```
     * ตรวจสอบผลลัพธ์ผ่าน `process.waitFor()` หากมีข้อผิดพลาดหรือระบบไม่ได้ติดตั้ง Potrace จะมีการแจ้งเตือนด้วย `CliToolNotFoundException` อย่างถูกต้อง
  4. **การรวมเลเยอร์ SVG (Layer Merging)**:
     * เนื่องจาก Potrace แปลงได้ทีละเลเยอร์ ระบบจึงอ่านแท็กพาธ `<g>...</g>` ของแต่ละไฟล์ SVG ที่ได้ แล้วเปลี่ยนค่าสี `fill` ให้ตรงกับสีจริงในแต่ละเลเยอร์ จากนั้นนำมารวมไว้ในไฟล์ SVG เดียวกัน
  5. **การลบพื้นหลังอัตโนมัติ (Background Removal)**:
     * หากเปิดใช้งานตัวเลือกลบพื้นหลัง ระบบจะตรวจสอบพิกเซลบริเวณมุมทั้ง 4 ของภาพ หากเป็นสีเดียวกันและมีสัดส่วนเกิน 5% ระบบจะข้ามการวาดเลเยอร์ดังกล่าว ส่งผลให้ได้ภาพเวกเตอร์แบบโปร่งใส

### ฟังก์ชันที่ 4: การประมวลผลแบบมัลติเธรดและการหน่วงเวลา (Concurrency & Debounce)
* **คลาสที่เกี่ยวข้อง**:
  * `BatchProcessor.java` (การประมวลผลกลุ่มแบบขนาน)
  * `MainViewController.java` (การจัดตารางเวลาและ Debounce)
* **หลักการและความรู้ที่ใช้**:
  * **การแยกงานอย่างชัดเจน (Single Responsibility)**:
    * แยกงานย่อยออกเป็นคลาส `PreprocessSingleTask` และ `ExportSingleTask` (ทำงานเป็น `Callable`) แทนการใช้ Anonymous Function ซ้อนกัน ช่วยให้ดีบักและติดตามการทำงานใน IDE ได้ง่าย
  * **ThreadPool และ CompletionService**:
    * ใช้ `ExecutorService` จัดการเธรดตามจำนวนแกนประมวลผล (CPU Cores)
    * ใช้ `ExecutorCompletionService` เพื่อให้รูปภาพที่ประมวลผลเสร็จก่อนสามารถส่งผลลัพธ์กลับมาอัปเดตแถบความคืบหน้า (Progress Bar) บนหน้าจอได้ทันทีแบบเรียลไทม์
  * **การทำ Debounce (หน่วงเวลา 300ms)**:
    * เมื่อผู้ใช้เลื่อนปรับจำนวนสีหรือค่าความละเอียดถี่ๆ ระบบจะใช้ `ScheduledExecutorService` หน่วงเวลาไว้ 300 มิลลิวินาที หากมีการเปลี่ยนค่าอีกก่อนหมดเวลา งานเดิมจะถูกยกเลิกทันทีเพื่อป้องกันการประมวลผลซ้ำซ้อนที่ไม่จำเป็น
  * **การจัดการความสอดคล้องด้วย AtomicLong (Generation Control)**:
    * ใช้ `AtomicLong` นับเลขเวอร์ชันของการพรีวิว หากผู้ใช้เปลี่ยนภาพหรือกด Reset งานเก่าที่ยังทำงานค้างอยู่บนเธรดเบื้องหลังจะไม่ส่งผลกระทบต่อหน้าจอ ป้องกันปัญหา Race Condition ได้ 100%
  * **ความปลอดภัยของเธรด UI**: การประมวลผลที่กินเวลานานทั้งหมดทำบน Worker Thread และส่งงานอัปเดตหน้าจอกลับมายัง JavaFX Application Thread ผ่าน `Platform.runLater()` เสมอ

### ฟังก์ชันที่ 5: หน้าจอแสดงผลและเปรียบเทียบภาพต้นฉบับกับภาพเวกเตอร์ (Side-by-Side Preview)
* **คลาสที่เกี่ยวข้อง**: `PreviewPane.java`
* **หลักการและความรู้ที่ใช้**:
  * **SplitPane**: แบ่งครึ่งซ้าย-ขวาอย่างละ 50% ให้ผู้ใช้สามารถเลื่อนแถบแบ่งเพื่อเปรียบเทียบรายละเอียดได้อย่างอิสระ
  * **WebView สำหรับเรนเดอร์ SVG**: ใช้เอนจิน WebKit ที่ติดตั้งมาพร้อมกับ JavaFX โหลดไฟล์ SVG ทำให้ภาพเวกเตอร์สามารถซูมขยายได้ไม่จำกัดโดยที่ภาพไม่แตก
  * **ลายตารางหมากรุกแสดงความโปร่งใส (Checkerboard Background)**:
    * วาดลายตารางสีเทาเข้มสลับเทาอ่อนลงบน `WritableImage` ผ่าน `PixelWriter` เพื่อเป็นพื้นหลังบอกความโปร่งใสของภาพแบบเดียวกับโปรแกรมแต่งภาพมืออาชีพ
  * **การซูมแบบประสานงาน (Synchronized Zoom)**:
    * ปุ่มซูมเข้า (1.2x), ซูมออก (0.8x) และซูมพอดีหน้าต่าง (Zoom to Fit) ทำงานพร้อมกันทั้งสองฝั่งอย่างแม่นยำ

### ฟังก์ชันที่ 6: การส่งออกไฟล์แบบกลุ่มและการจัดการชื่อไฟล์ (Batch Export & Sanitization)
* **คลาสที่เกี่ยวข้อง**: `BatchProcessor.java`, `MainViewController.java`
* **หลักการและความรู้ที่ใช้**:
  * **กฎการตั้งชื่อไฟล์**:
    * ใช้ชื่อเดิมของไฟล์ (เช่น `picture.png` -> `picture.svg`)
    * กำหนดคำนำหน้าพร้อมลำดับเลข (เช่น `icon_1.svg`, `icon_2.svg`)
  * **การล้างชื่อไฟล์ที่ไม่ปลอดภัย (Name Sanitization)**:
    * ตรวจจับและแปลงอักขระพิเศษที่ระบบปฏิบัติการไม่อนุญาต เช่น `\ / : * ? " < > |` ให้กลายเป็นเครื่องหมายขีดล่าง `_` เพื่อป้องกันโปรแกรมหยุดทำงานขณะเขียนไฟล์ลงดิสก์
  * **ความทนทานต่อข้อผิดพลาด (Fault Tolerance)**: หากมีไฟล์รูปภาพใดเสียหาย การประมวลผลไฟล์อื่นๆ จะยังคงดำเนินต่อไปจนเสร็จสิ้น และสรุปจำนวนภาพที่สำเร็จและล้มเหลวให้ผู้ใช้ทราบในตอนท้าย

## 3. ตารางสรุปเทคโนโลยีและความรู้ที่นำมาใช้ (Technical Summary Table)

| หัวข้อ | เทคโนโลยี / เทคนิคที่ใช้ | ตำแหน่งในโค้ด |
|--------|-------------------------|---------------|
| **รูปแบบสถาปัตยกรรม** | MVC Pattern, Single Responsibility, Callback, Dependency Injection | โครงสร้างโปรเจกต์ทั้งหมด |
| **ส่วนติดต่อผู้ใช้ (GUI)** | JavaFX 26, FXML, SplitPane, WebView, WritableImage | แพ็กเกจ `view` |
| **การทำงานพร้อมกัน (Concurrency)** | `ExecutorService`, `CompletionService`, `ScheduledExecutorService`, `AtomicLong` | `BatchProcessor`, `MainViewController` |
| **อัลกอริทึมการประมวลผลภาพ** | K-Means Clustering, Pixel Sampling, Euclidean Color Distance, PPM P6 Generation | `VectorizationService`, `ColorAnalyzer` |
| **การสื่อสารกับกระบวนการภายนอก** | `ProcessBuilder`, Standard Stream Redirection, Exit Code Verification | `VectorizationService` |
| **ระบบไฟล์และความปลอดภัย** | `ZipInputStream`, การป้องกัน Path Traversal (ZIP Slip), การทำ File Name Sanitization | `ZipHandler`, `BatchProcessor` |
| **คุณภาพของโค้ด (Clean Code)** | โค้ดอ่านง่าย ไม่ใช้ Method Reference (`::`) ซับซ้อน เพื่อให้วาง Breakpoint ดีบักได้ง่าย | ทุกคลาสที่ได้รับการปรับปรุง |

## 4. ข้อแนะนำสำหรับการนำเสนอผลงาน (Presentation & Defense Tips)

1. **การสาธิตหน้าจอจริง (Live Demo)**:
   * ลากไฟล์ภาพสีเข้ามาในโปรแกรม และแสดงให้เห็นภาพเปรียบเทียบซ้าย-ขวาที่ชัดเจน
   * สาธิตการปรับจำนวนสีจาก 2 สีเป็น 4 สี แสดงให้เห็นความเร็วในการแปลงภาพแบบเรียลไทม์และการหน่วงเวลา (Debounce)
   * สาธิตการลากไฟล์ `.zip` เข้ามา แสดงแถบความคืบหน้าที่ทำงานแบบขนาน และกด Export ภาพทั้งหมดออกมาเป็น SVG
2. **จุดเด่นด้านโค้ดและสถาปัตยกรรมที่ควรเน้นตอบอาจารย์**:
   * **สถาปัตยกรรม MVC ชัดเจน**: ส่วนติดต่อผู้ใช้และอัลกอริทึมแยกออกจากกันอย่างสมบูรณ์
   * **Clean Code**: ฟังก์ชันหลักมีขนาดกะทัดรัด แยก Task ชัดเจน ทำให้สามารถเปิด Debugger กระโดดเข้าดูการทำงานภายในเมธอดได้อย่างง่ายดาย
   * **ความปลอดภัยและความเสถียร (Robustness)**: มีการป้องกัน ZIP Slip, การตรวจสอบความถูกต้องของชื่อไฟล์, และการใช้ Atomic Generation ป้องกันการแสดงผลพรีวิวสลับกันในระบบมัลติเธรด
